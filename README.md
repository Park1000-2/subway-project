# 앉아서 가기 — 지하철 착석 확률 프로토타입

집 역·회사 역과 시각을 넣으면, **제약을 지키면서 가장 앉을 가능성이 큰 열차**를
찾아 주는 웹 프로토타입입니다. 출근과 퇴근을 모두 지원합니다.

**'무슨 길'과 '시각 기준'은 별개입니다.** 묶어 두면 출퇴근 외의 이동을 못 다룹니다.

| 무슨 길 | 역 | 시각 기준 |
|---|---|---|
| **출근** | 집 → 회사 | 도착(`arrive`) 고정 |
| **퇴근** | 회사 → 집 | 출발(`depart`) 고정 |
| **다른 곳** | 출발역 → 도착역 (입력한 그대로) | 직접 선택 |

출퇴근은 조합이 뻔해서 묶어 두고, '다른 곳'일 때만 기준을 고르게 합니다. 전환하면
라벨이 따라 바뀌고(집 역 ↔ 출발역), 기준 시각은 현재 시각으로 맞춰집니다.

시각 기준 두 가지는 제약 방향이 반대입니다.

| 기준 | 제약 | 피하고 싶은 비용 |
|---|---|---|
| **도착**(`arrive`) | 목표 시각까지 **도착** | 불필요하게 이른 출발 |
| **출발**(`depart`) | 그 시각 **이후**에만 승차 | 역에서의 긴 대기 |

둘 다 '제약을 지키는 열차 중 비용이 작고 앉을 가능성이 큰 것'을 고르는 문제라
점수식은 공유합니다 (`planCommute` 의 `o.cost`).

> 지금 화면의 혼잡도는 **추정 모델** 값입니다. 실측이 아닙니다.
> 정의와 구조는 실데이터와 같게 맞춰 두었으므로, 아래 '실데이터 연결'대로
> 소스를 끼우면 같은 UI가 그대로 실측 기반으로 동작합니다.

## 실행

ES 모듈을 쓰므로 `file://` 로 열면 안 되고 정적 서버가 필요합니다.

```bash
cd ~/Documents/subway-project
python3 -m http.server 8000     # 또는  npx serve .
# http://localhost:8000
```

```bash
cd ~/Documents/subway-project
git init && git add -A && git commit -m "앉아서 가기"
```

## 즐겨찾기

자주 타는 구간은 **조건 전체**(집·회사 역, 출퇴근 기준, 시각, 요일, 경로 기준,
여유/한도, 도보 시간)를 묶어서 저장합니다. 칩을 누르면 그대로 불러와 다시 계산하고,
현재 입력과 같은 칩은 강조 표시됩니다. 최대 12개.

같은 집·회사라도 **출근과 퇴근을 따로 저장**하는 걸 전제로 했습니다 — 시각도 방향도
다르니까요. 칩에는 실제 진행 방향으로 표시됩니다(퇴근이면 `강남 → 서울역`).
'다른 곳'으로 저장한 구간은 `출발`/`도착` 으로 구분해 표시합니다.
예전 형식(`basis`만 있던 것)은 불러올 때 자동으로 변환됩니다.

저장 위치는 브라우저 `localStorage` 라서 **그 브라우저에서만** 보입니다. 기기 간
동기화는 안 되고, 시크릿 창이나 사이트 데이터를 지우면 사라집니다.

## 모델

### 1. 혼잡도

서울교통공사 정의를 그대로 씁니다. **혼잡도(%) = 승차 인원 ÷ 열차 정원 × 100**,
**좌석이 모두 찬 상태 = 34%** (`SEAT_FULL`).

구간 혼잡도는 중력모형으로 만듭니다.

- 오전에는 주거 가중치 `r` 에서 승차해 업무 가중치 `j` 로 하차합니다(저녁은 반대).
- 역 `i` 에서 탄 승객은 진행 방향 하류의 역 `k` 중 `j_k` 에 비례해 목적지를 고릅니다.
- 구간 `s` 의 적재량 = `Σ_{i≤s} Σ_{k>s} flow(i,k)` (차분배열로 O(n²))
- 시각 가중은 `am` / `pm` / `day` 세 곡선의 합이며, 30분 단위 앵커 테이블
  (`CURVES` in `congestion.js`)로 되어 있어 **실측 30분 단위 혼잡도로 그대로 교체**할 수 있습니다.
- 노선별로 `LINE_PEAK` (평일 최고 혼잡도)에 맞춰 정규화합니다. 상하선·요일 차이는
  방향별·요일별로 따로 계산됩니다.

### 2. 착석 확률

- 승차 시점 혼잡도가 34% 미만이면 남은 좌석에 바로 앉습니다.
- 그보다 붐비면, 지나는 역마다 생기는 빈 좌석을 주변 입석 승객과 경합합니다.
  `p = freed / (freed + standees × α)`, `α = 1.5`.
  α = 1.0 이 '모든 입석이 빈 좌석을 동등하게 얻는' 중립 기준이고, 그보다 큰 값은
  좌석 앞에 이미 서 있던 사람이 먼저 앉는 몫입니다. 체감과 비교해 조정하세요 —
  `congestion.js` 의 `SEAT_COMPETITION` 한 줄입니다.

  | α | 서울역→강남 | 신림→강남 | 수유→합정 | 상계→여의도 |
  |---|---|---|---|---|
  | 1.0 | 38% | 47% | 70% | 97% |
  | 1.3 | 31% | 39% | 61% | 97% |
  | **1.5** | **28%** | **35%** | **57%** | **97%** |
  | 1.8 | 24% | 30% | 50% | 96% |
  | 2.2 | 20% | 25% | 44% | 96% |
- **빈 좌석 `freed` 는 좌석/입석을 나눠서 셉니다.** 역 k 에서 내리는 사람 중
  '앉아 있던' 비율을 φ 라 하면 `freed = φ × 하차비율 × 혼잡도` 입니다.
  좌석/입석을 구분하지 않으면 φ = 좌석 비율(34/혼잡도)이 되어 예전 식과 같아집니다.
- 역마다의 `p` 를 누적해 **하차 전에 앉을 확률**과 **앉아서 가는 구간 비율**을 함께 냅니다.
  두 값이 크게 벌어지면 '앉긴 앉는데 거의 다 와서 앉는다'는 뜻입니다.
- 하차 비율은 중력모형의 목적지 분포에서 나오며, SK Open API 의
  **'진입 역 기준 칸별 하차 비율'** 로 교체할 수 있는 자리입니다.

### 3. 승차 실패 / 추천 점수

- 못 탈 위험 = `clamp((c − 130) / 75, 0, 0.8)` — 혼잡도 150%에서 약 27%.
- 추천 점수 = `앉아가는 비율×100 − 못 탈 위험×65 − 비용×0.22`.
  비용은 출근이면 '불필요하게 이른 출발', 퇴근이면 '역에서의 대기'입니다.
  제약을 어기거나(지각 / 나서기 전 열차) 허용 범위를 넘기면 제외.
- 창 밖에 **눈에 띄게 더 앉을 수 있는 열차**가 있으면 '대안'으로 따로 보여 줍니다
  (희생이 가장 적은 열차 1대만).

### 4. 탈 칸과 내릴 칸은 다를 수 있다

빠른 환승 위치가 2-1이라고 해서 2호차에 타야 하는 건 아닙니다. 한산한 칸에 타서
앉아 가다가, 내리기 전에 차내로 이동하면 됩니다. 모델은 그 맞바꿈을 칸마다 계산합니다.

- **이동 시점은 최대한 늦게.** 일찍 옮기면 앉은 자리를 그만큼 일찍 버립니다.
  마지막 네 정거장 중 통로가 막히지 않는(`moveDifficulty`) 가장 늦은 역을 고릅니다.
- **그 역에서 자리를 뜬다고 보고 착석 시간을 끊습니다** (`seatForCar(..., untilIndex)`).
  그래서 '끝까지 앉아 가는 확률'과 '이동을 감안한 확률'이 따로 나옵니다.
- **통로 이동 난이도**는 이동 시점의 혼잡도로 매깁니다 —
  70% 미만 쉬움 / 110% 미만 보통 / 150% 미만 어려움 / 그 이상 거의 불가.
  혼잡할수록 이동 비용이 커져서, 붐비는 시간엔 '하차 칸에 그대로 타기'가 이깁니다.
- 화면에는 **하차 칸에 그대로 / 추천 / 앉을 확률 최대** 세 가지를 나란히 놓고 고르게 합니다.

### 5. 칸별 혼잡도와 빠른 환승

칸별 혼잡도는 양 끝 칸이 한산한 대칭 U자형 보정계수(평균 1.0)로, **역별 실제
환승 통로 위치는 반영되지 않은 추정값**입니다.

반면 **빠른 환승 위치(몇 호차 몇 번째 문)와 환승 소요시간은 실데이터**입니다.
두 값은 대체로 충돌하므로(환승 통로 쪽 칸이 더 붐빔) 화면에서는 둘을 나란히
보여 주고 선택은 사용자에게 맡깁니다 — '앉고 싶으면 끝 칸, 환승이 급하면 N호차'.

### 두 데이터의 성격이 다릅니다

| | 서울교통공사 환승정보 | 국가철도공단 환승정보 |
|---|---|---|
| 범위 | 서울교통공사 운영 노선 중심 | 운영기관별 26종(신분당·코레일·공항철도 포함) |
| 타고 온 방향 구분 | **있음** | 없음 |
| 승차 위치 | 있음 | 없음 |
| 환승 소요시간 | 있음 | 없음 |
| 위치 개수 | 조합당 1개(최단) | 조합당 1~2개 |

그래서 서울교통공사 쪽을 우선 적용하고, 없는 조합만 국가철도공단으로 메웁니다.
국가철도공단 쪽에 위치가 둘이면 보통 **진행 방향별 하차 위치(서로 거울 관계)** 라
어느 쪽인지 단정할 수 없어, 화면에 둘 다 표시하고 그렇다고 밝힙니다.

### '방면'은 이름이 아니라 방향으로 해석합니다

같은 '방면'인데 데이터마다 인접역이기도 하고(일반), 몇 정거장 건너뛴 급행 정차역이기도
하고(공항철도), 그냥 방향 표시역이기도 합니다(동대문역사문화공원 → '을지로입구').
이름을 그대로 맞추면 멀쩡한 기록이 버려지므로, 노선 위 상대 위치로 **방향(+1/-1)만**
뽑아서 키를 잡습니다. 이 한 가지 변경으로 커버리지가 90% → 94%로 올랐습니다.

노선 표기도 파일마다 `경의중앙선`/`경의중앙`처럼 달라서 '선' 유무를 모두 봅니다.
역명은 전국에서 겹치므로(부산에도 교대역이 있습니다) 모든 행을 `network.js` 와
대조해 검증하고, 맞지 않으면 버립니다.

### 5. 좌석에서 내리는 비율 φ

중력모형은 `flow(i, k)` — i에서 타서 k에서 내리는 양 — 라는 **결합분포**를 계산합니다.
혼잡도에는 그 주변분포만 필요하지만, 좌석 회전을 보려면 결합분포가 있어야 합니다.

- 구간마다 **승차 위치별 잔존 인원**(`onboard[p]`)을 유지합니다.
- 좌석은 **먼저 탄 사람 순서로** 배정합니다 — 종점 쪽에서 타면 앉고, 늦게 타면 섭니다.
- 역 k 에서 내리는 사람 중 좌석 점유자의 몫이 φ 입니다.

수도권 3호선 하행 오전 8시 기준으로 φ 는 **좌석 비율의 1.4~1.6배**로 나옵니다.
멀리서 탄 사람이 앉아 있다가 도심에서 한꺼번에 내리기 때문입니다. 이 보정만으로
어떤 출근 경로의 착석 확률이 15% → 21%, 같은 구간 퇴근이 23% → 36%로 올랐습니다.

계산은 노선당 `n × maxSpan` 한 번의 스윕이라 프로파일 생성 전체가 45ms입니다.

**근사 하나**: φ 는 각 시간대 곡선의 최고 가중 상태에서 계산한 뒤 시각 가중으로
섞습니다. 한산한 시간대에는 실제보다 φ 를 낮게 잡지만, 그때는 승차 즉시 착석
항이 지배하므로 영향이 작습니다.

φ 를 넣은 뒤 경합 계수 α 를 2.2 → 1.5 로 내렸습니다. 2.2 는 φ 가 없던 시절
'빈 좌석이 과대 계산되는 것'까지 떠안고 있던 값이라, φ 가 제 역할을 하는 지금은
이중으로 보수적이었습니다.

## 알려진 한계

- 역 목록은 1~9호선·신분당·수인분당·경의중앙·공항철도의 **주요 구간만** 수록했습니다.
  일부 외곽 구간과 2호선 성수지선 등이 빠져 있습니다.
- **급행·특급을 구분하지 않습니다.** 9호선 급행처럼 혼잡도와 소요시간이 완전히 다른
  열차가 일반 열차로 계산됩니다.
- 열차 시각표는 배차간격 추정이라 실제 시각표와 분 단위로 다릅니다. 역별 위상은
  기점에서의 주행시간으로 근사했습니다.
- 칸별 혼잡도는 역의 계단·환승 통로 위치를 반영하지 않습니다(환승 위치 자체는 실데이터).
- 환승정보 커버리지는 94%입니다. 남은 6%는 주로 **신분당선 연장 구간(신사·논현·신논현)**,
  청량리 수인분당선처럼 최근 개통분이라 공개 데이터에 아직 없습니다.
